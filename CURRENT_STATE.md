# Фактическое состояние SpaceOS

Срез: 2026-10-18. Проверен локальный исходный проект; HEAD на момент анализа — 7990bd9f525bbe626ed5be07bf3c964270028ae4. Это идентификатор исходного проекта, не коммита публикации документации.

## Что подтверждено и каким способом

Концепция World/Shell подтверждена владельцем проекта. Основные документы изучены с учётом поздних дополнений; ключевые утверждения сопоставлены с текущим кодом.

Присутствуют семь workspace-модулей, модель Core и SQLite, файловый и браузерный провайдеры, Bridge, 20 MCP-инструментов, Mission Workflow, World/Shell и опциональная Wry-оболочка.

При подготовке документации приложение, сборка и тесты не запускались. Старые результаты проверок не представлены как свежая проверка HEAD. Работающие процессы, текущие бинарные файлы и содержимое пользовательской базы не исследовались.

## Концепция и текущая реализация

| Подтверждённое решение | Реализовано | Граница или расхождение |
|---|---|---|
| World — основной экран | Корневой HTTP-маршрут открывает world.html | Основной экран не объединяет все подробные сценарии: создание и ведение миссий переводят в Shell |
| Shell — дополнительный структурированный интерфейс | index.html, семь тематических разделов и переходы из World | Некоторые переходы открывают Shell целиком, без выбора конкретной миссии или раздела |
| Общая модель для представлений | Оба UI читают данные через Bridge/Core | В коде UI также есть статические пояснения; не каждый текстовый индикатор является живой проверкой |
| Нативное окно существующей оболочки | Wry/WebView2 feature и путь запуска реализованы | Самостоятельный fallback runtime показывает другой встроенный UI; это не основной World |
| Взаимодействие с браузером через провайдер | CDP-действия, содержимое страницы и кадры | Текущая панель — изображение; интерактивный iframe, упоминаемый старым текстом, не подтверждён |

Различия отражают степень реализации и неточности прежних описаний. Документация не назначает их исправление обязательным планом и не меняет исходный код.

## Ограничения системы

- world_id — контекст и фильтр, а не полная многопользовательская изоляция; права мутаций и доступ к подпискам проверяются различными путями.
- Core хранит данные, но сохраняет и прежние методы записи отдельных сущностей; единственный обязательный путь всех мутаций через Observation не реализован.
- Согласования миссий — проверки workflow в Bridge, не универсальная Policy-защита всех действий.
- Внешние эффекты не атомарны с записью в SQLite. Повтор запроса действия может повторить эффект; таймаут не доказывает отмену.
- Маршрутизатор действий выделяет browser и файловый маршрут; универсального динамического диспетчера провайдеров нет.
- Буферы SpaceTrace локальны процессам; все события истории не передаются через WebSocket Bridge.
- Агентные токены и подписки не сохраняются как продолжение активной сессии после рестарта.
- Не реализованы Git-провайдер и программный запуск OpenCode; встроенный автономный оркестратор отсутствует.
- Ограничения файловых путей не устраняют все гонки между проверкой и использованием ресурса.
- Безопасность удалённого сетевого развёртывания не подтверждена. Bridge по умолчанию локальный; его маршрутизатор использует permissive CORS, а UI-действия выполняются под серверным актором.
- Долговременная устойчивость и масштабирование не имеют универсальных эксплуатационных гарантий.

## Сборка и запуск полного проекта

Репозиторий содержит исходный код приложения и следующие точки входа:

| Назначение | Точка входа |
|---|---|
| Сборка workspace | cargo build --workspace |
| Нативное окно | cargo build --release -p runtime --features wry-wrapper |
| Запуск через Chromium | launch.ps1 -Shell |
| Запуск нативной оболочки | launch.ps1 -Native |
| Остановка | stop_spaceos.ps1 |
| Проверки | run_tests.ps1, verify_spaceos.ps1, check_mcp_tools.ps1, check_shell_ui.mjs |

Основная среда — Windows, Rust/Cargo, PowerShell; для браузерного провайдера требуется Chromium/CDP, для нативного окна — WebView2. Отдельные UI-проверки используют JavaScript runtime. Минимальные поддерживаемые версии не оформлены как проверенная матрица.

Launcher и служебные сценарии учитывают конкретное размещение проекта; переносимость установки не заявляется. Проверки с общими каналами IPC и портами требуют изоляции от рабочего стека и тестовых данных.

Значения токенов, пользовательские пути и локальные настройки в публикацию не включены.
