# SpaceOS

SpaceOS — локальная рабочая среда поверх Windows, объединяющая файлы, вкладки браузера, миссии и действия агентов в общей модели объектов, связей и событий.

Этот репозиторий содержит актуальный исходный код SpaceOS и техническую документацию. Рабочие данные, секреты, локальные настройки и результаты сборки не включены.

## Подтверждённая концепция

**World — основной экран и главная точка взаимодействия.**

**Shell — дополнительный интерфейс для более структурированного представления системы, навигации по разделам и инструментам.**

Оба интерфейса используют общую доменную модель Core. Это подтверждённое архитектурное решение; степень его реализации описана отдельно в [CURRENT_STATE.md](CURRENT_STATE.md).

## Реализованные возможности

- Общая модель объектов, связей, пространств и событий в SQLite.
- Наблюдение за файловой системой, сканирование и файловые операции в разрешённых каталогах.
- Управление вкладками Chromium через CDP, чтение содержимого страниц и получение кадров.
- World с пространственным представлением и режимами Space, Tree, Graph, Focus.
- Shell с разделами Workspace, Files, Browser, Agent, Tasks, Activity и System.
- Миссии с шагами, согласованиями, привязкой действий, свидетельствами результата и проверкой завершения.
- MCP-сервер с 20 инструментами для внешнего агента и контролируемые вызовы внешних MCP-серверов.
- Опциональное нативное окно интерфейса через Wry/WebView2.
- Диагностика действий и подсистема наблюдаемости SpaceTrace.

«Реализовано» здесь означает наличие соответствующего пути в коде. При подготовке этой редакции новый запуск приложения или тестов не выполнялся.

## Архитектура в одном абзаце

Core хранит доменное состояние и проверяет права. Провайдеры выполняют файловые и браузерные операции и сообщают наблюдения Core. Bridge предоставляет HTTP/WebSocket API, MCP-интерфейс и workflow миссий. World и Shell отображают общую модель; внешний агент использует MCP. SpaceTrace помогает диагностике и не владеет состоянием системы.

Файлы и вкладки существуют во внешней среде. SQLite хранит их представление, миссии и историю; повторное сканирование файлов не восстанавливает всю историю проекта.

## Модули

| Модуль | Назначение |
|---|---|
| space-core | Доменная модель, SQLite, Policy, события и IPC |
| filesystem-provider | Файловые наблюдения и операции |
| browser-provider | Вкладки и действия Chromium через CDP |
| space-bridge | HTTP/WebSocket, миссии, MCP server/client |
| runtime | CLI, встроенный UI и опциональная Wry-оболочка |
| spacetrace | Наблюдаемость и корреляция |
| agent-demo | Демонстрационный клиент Core |

Основной стек: Rust, Tokio, rusqlite/SQLite, HTML и JavaScript; для HTTP используется Axum.

## Изучение и сборка после клонирования

Начните с ARCHITECTURE.md и MODULES.md; реализация находится в каталогах семи модулей, тесты — в их tests/ и исходных модулях. World/Shell расположены в space-bridge/static/, встроенный UI runtime — в runtime/static/.

Для сборки из корня репозитория используйте cargo build --workspace --locked. Cargo.toml и Cargo.lock включены; Rust-зависимости загружаются Cargo. Команда приведена как инструкция и в рамках подготовки публикации не запускалась.

Основная платформа — Windows. Для запуска браузерного провайдера нужен отдельно установленный Chromium с CDP; браузерный бинарный файл и профиль не входят в репозиторий. Опциональное нативное окно требует WebView2 и сборки runtime с --features wry-wrapper. Проверки .mjs рассчитаны на Node.js; check_shell_ui.mjs указывает Node.js 18+.

Часть исходных сценариев и значений по умолчанию привязана к C:\spaceos. Это сохранённое ограничение реализации: клонирование в другую папку достаточно для чтения кода, но не гарантирует готовность всех скриптов к запуску. Не запускайте их против чужой рабочей установки. launch.ps1 имеет параметры WorkDir, ChromePath, WatchPath, ProfileDir и LogDir; некоторые остальные сценарии содержат фиксированные пути. Пользовательские профили, конфигурация MCP и рабочая база должны создаваться отдельно.

Документы со ссылками на исторические docs/ перечисляют источники анализа исходного проекта, а не обязательные зависимости сборки. Архивные отчёты в публикацию не включены. Сборка и тесты после клонирования ещё не проверены.
