# Модули и интерфейсы

Срез: 2026-10-18. Cargo workspace содержит семь модулей.

## Ответственность модулей

| Модуль | Реализация | Граница ответственности |
|---|---|---|
| space-core | Object, Relation, Event, Space, Observation; SQLite; Policy; IPC; подписки | Владеет моделью, маршрутизирует действия; внешние операции выполняют провайдеры |
| filesystem-provider | Scanner, watcher, идентичность и форматы файлов, корни доступа, файловые действия, наблюдение процессов Windows | Сообщает наблюдения Core, не ведёт отдельное доменное хранилище |
| browser-provider | CDP-соединения, состояние вкладок, навигация, содержимое страниц, снимки | Chromium остаётся внешним процессом |
| space-bridge | Axum HTTP API, WebSocket статусов, static UI, Mission Workflow, MCP server/client | Проверяет workflow и внешний allow-list; состояние сохраняет через Core |
| runtime | spaceos CLI, объединённый запуск Core/FS, встроенный HTTP UI, опциональное Wry-окно | Отдельный launcher организует основной многопроцессный стек |
| spacetrace | Хуки, буфер, корреляция, диагностические оценки, Windows ETW backend | Опциональная наблюдаемость |
| agent-demo | Демонстрационный агент, регистрация и действия через IPC | Не автономный планировщик |

Основные исполняемые компоненты: space-core, filesystem-provider, browser-provider, space-bridge, spaceos-mcp, spaceos и agent-demo. MCP-бинарный файл входит в модуль space-bridge; spacetrace используется как библиотека.

## Файловый контур

Провайдер реализует create, read, write, rename, move, copy и delete. Сканирование выполняется как асинхронная работа. Bridge предоставляет операции списка, поиска, чтения, создания, записи и запуска сканирования.

Текстовое чтение рассчитано на UTF-8 и ограничено 256 КиБ. Создание проверяет существование файла; запись может проверять переданные клиентом признаки конфликта. Эти проверки не являются полноценной защитой от всех конкурентных изменений.

Идентичность файлов и согласование scanner/watcher используют наблюдаемые признаки и обработку неопределённости. Не заявляется безошибочная идентичность для любых копирований, блокировок и внешних переименований.

## Браузерный контур

Действия провайдера включают навигацию, обновление, получение вкладок и содержимого страницы, создание, активацию и закрытие вкладки, получение снимка через CDP.

World показывает кадры выбранной вкладки. Нажатия по странице внутри кадра не передаются Chromium. Нативное окно оболочки и управляемая CDP-вкладка — разные поверхности.

MCP предоставляет только перечисленные ниже браузерные инструменты; возможности UI и провайдера шире этого списка.

## MCP-сервер: 20 инструментов

| Группа | Инструменты |
|---|---|
| Состояние и история | spaceos_status, spaceos_actions, spaceos_action_status, spaceos_trace |
| Браузер | browser_tabs, browser_navigate, browser_reload, browser_get_state, browser_get_content |
| Файлы | filesystem_roots, filesystem_scan, filesystem_list, filesystem_search, filesystem_read_file, filesystem_create_file, filesystem_write_file, filesystem_job_status |
| Миссии | mission_get, mission_update |
| Внешние инструменты | external_mcp_call |

spaceos_trace возвращает диагностическую цепочку событий действия; это не объединённый персистентный буфер всех процессов.

Исходящий MCP-клиент работает с локально зарегистрированными серверами, allow-list инструментов и проверкой аргументов по обнаруженной схеме. Произвольная исполняемая программа не выбирается клиентским запросом. Сведения о результате вызова сохраняются в Core.

## Миссии

Миссия содержит цель и упорядоченные шаги. Workflow включает планирование, выполнение, ожидание согласования, проверку, завершение, неудачу и отмену. Повтор достигнутого состояния не создаёт новое изменение.

Шаги хранят свидетельства результата и идентификаторы действий. Проверка завершения и требования согласования реализованы в Bridge. Core хранит соответствующие объекты, связи и события.

Планирование и выполнение агентного цикла происходят во внешнем runtime. Отображаемые акторы отражают наблюдаемую активность; online-статус агента отдельно не гарантируется.

## Интерфейсы

World: пространственное представление, Tree, Graph, Focus, выбор объектов, сведения о связях, браузерная панель и переходы к инструментам Shell.

Shell: Workspace, Files, Browser, Agent, Tasks, Activity, System; редактор файлов, специализированные действия, workflow миссий и просмотр истории.

Наличие обоих интерфейсов не означает два независимых backend. Исходный код и UI-ресурсы включены с сохранением структуры Cargo workspace.
